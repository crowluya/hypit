# Hypit KIE / fal 改造与真实拉片自测

日期：2026-11-05。开发自测记录，不代表独立QA通过。

## 实现

基于上游 `hypit-ai/hypit` 的 `67c15455`，新增 KIE/fal 原生 Provider、显式选择服务的拉片 CLI、任务回执、媒体上传缓存、独立词级转写、逐镜视频分析和离线报告。保留 Hypit 原有默认 Runtime；生成请求由新的示例 Profile 显式绑定。没有修改用户原有 Soap2Soap 服务、数据库或配置。

原生生成适配覆盖 KIE/fal Nano Banana 2、KIE Seedance Mini、fal Grok Imagine Video。参数映射、限制拒绝、凭据引用、回执保存、查询与收集已通过自动化和 Runtime 配置检查；本轮未提交这些生图/视频生成模型的付费真实生成，不能声称它们的生成效果已验收。

## 遇到的真实失败与处理

1. KIE全片视频分析返回应用层 `524`，未取得全片内容结果。保留未完成回执，没有重提同一请求；不能宣称整条KIE视频分析路径成功。
2. 上传文件名最初缺少扩展名，已修正为按媒体类型保留 `.mp4`、`.mp3`、`.jpg` 等。无法仅凭该修复断言它就是 KIE `524` 的原因。
3. 显式改用已授权的fal视频理解后，首个任务返回HTTP 422，查询原任务确认提示词超过5000字符。已保留失败任务ID，改为按说话轮次压缩转写；修正后的独立请求完成。完整248词没有截断。
4. 全片分析返回带time/event的剧情节点对象，已补上保留原文的结构转换，复用原始结果，没有为解析问题重新调用模型。
5. 最后一镜采样越过视频结尾，发现容器总时长包含略长的音频尾部。现在独立探测视频轨道时长并留采样余量，复跑复用前22个区间，仅补齐最后一镜。

没有按真实账单核算费用；请求回执和Provider账单才是核对成本的依据。

## 语义和切点质量

- 49.40–50.10秒的独立区间现在识别为女孩打电话；KIE针对独立图片的复核也确认49.77秒为街头女孩，排除了上次的办公室父亲误配。但模型对地点仍有“商店街或室内”的不确定描述。
- 39.466667–49.40秒区间实际跨越街头女孩与办公室父亲的渐变切换。源帧与KIE图片复核共同确认切换发生在45.80–47.00秒之间，精确切点未逐帧标注。该区间已自动标记“镜内存在画面切换，需要拆分复核”。
- 54.60–64.90秒区间的模型描述同样包含画面切换，已标记复核。这证明“候选区间全覆盖”不能当作“每个摄影镜头都准确拆开”。
- 原片部分保安在不同画面中外形明显变化，全片角色表和区间人物归属仍需人工校对。声音编号没有自动认定为视觉人物。

保留模型原始结果，没有把这些问题偷偷改成“已正确”。下一步应细化渐变切点、人工拆分合并和角色/台词矫正，再评估复刻生成。
